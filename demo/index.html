Diagnosis

Why it blows out, and why it flickers

Overexposure

  1. No tone mapping.WebGLRenderer defaults to NoToneMapping. Anything above 1.0 hard-clips to flat white.
  2. Stacked lights.Ambient 0.6 + hemisphere 0.8 + sun 2.5 + "fill" 1.0. Each looked fine alone; together a white wall lands 3–4× past clip.
  3. Point lights with no falloff.decay: 0 lights everything at full strength, at any distance.
  4. Composer without OutputPass.Render targets skip the renderer's tone mapping. Only OutputPass applies ACES, exposure and sRGB.
  5. Bloom below threshold 1.0.Bloom runs on linear HDR before tone mapping, so a sunlit wall is already ~1.0. Lower thresholds turn the frame into fog.

Flicker

  1. Shadow swimming.A sun that follows the player moves the shadow map by fractions of a texel every frame. Edges crawl. Fix: snap to texels.
  2. Shadow acne.Zero bias and normalBias: surfaces shadow themselves in moving stripes.
  3. Specular fireflies.Metal at roughness < 0.15 makes sub-pixel highlights that sparkle, then bloom turns each into a star.
  4. Composer drops MSAA.new EffectComposer(renderer) has no multisampling, so antialias: true silently stops working.
  5. Random flicker effects.Math.random() per frame at 60–144 Hz is a strobe, not a candle.
  6. Z-fighting.Coplanar decals or a near plane of 0.001. Lift decals, keep near ≥ 0.1.

The tone curve

What ACES does to a white wall

Lit values in a physical scene routinely exceed 1.0. Without tone mapping, every value past 1.0 becomes the same white. ACES filmic compresses that range into a shoulder, so a wall at 2× or 4× still shows its shading. Hover the chart to read values.

Pipeline

Where each fix sits in the frame

createComposer() builds this chain. The order matters: bloom must see linear HDR values, and OutputPass must be last.

  1. 1 · Scene

    Linear HDR lighting

    Physical lights, decay 2, budget ≈ 3.5. Values above 1.0 are normal here.

    tameLights()
  2. 2 · Target

    Half-float, 4× MSAA

    Keeps HDR values and restores the antialiasing the composer drops.

    HalfFloatType · samples: 4
  3. 3 · Bloom

    Only true highlights

    Runs before tone mapping, so the threshold is in scene units.

    threshold 1.0 · strength 0.35
  4. 4 · OutputPass

    ACES × exposure → sRGB

    The one place the curve above is applied.

    toneMappingExposure 0.9
  5. 5 · Check

    Measure the frame

    Read back the drawn pixels; adjust exposure once if needed.

    clipped < 2 % · mean 0.30–0.55

Light budget

Starting intensities

Meters, physical light units, ACES at exposure 0.9. The rule that prevents most blow-outs: ambient + hemisphere + directional ≲ 3.5, minus about 1.5 for each 1.0 of environment-map intensity. Need it brighter? Raise the key light, not the fill.

DirectionalLight (sun / key)2.51.5–3.0One key light. A white surface facing it ≈ 0.8–1.0 linear.

PointLight / SpotLight4 × d²—d = metres to the surfaces it lights. Street lamp at 5 m ≈ 100. Decay 2, always.

Use

Prompts that trigger it

For new work you don't need to mention the skill. Ask for the scene and the setup comes with it:

Build a three.js night street with lamps, a neon sign and a car I can drive.

To fix something that already exists, name the symptom:

This three.js artifact is blown out and the shadows flicker. Fix the lighting.

Retrofitting by hand takes four calls after your scene is built:

import { setupRenderer, tameLights, createComposer, calibrateExposure }
  from './hdr-lighting.js';

setupRenderer(renderer);
tameLights(scene);
const post = createComposer(renderer, scene, camera);
renderer.setAnimationLoop(() => post.render());
await calibrateExposure(renderer, () => post.render());

Verify before calling it done: auditLighting() shows no high rows, clipped pixels stay under 2 %, and orbiting the camera for a few seconds shows still shadow edges and no sparkle on metal.
